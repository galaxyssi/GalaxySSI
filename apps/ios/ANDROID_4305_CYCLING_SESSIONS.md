## iOS changes

- Separate Codable cycling session ledger, preserving decoding of the previous
  encrypted motion ledger. No migration into the measurement or care archive.
- Enter/pedalling, exit, still, foot and motor signals, ordered and deduplicated.
  Ambiguous classifications are ignored rather than treated as exits.
- Missing-enter candidate: two pedalling observations at least 15 seconds apart
  with at most 90 seconds between samples. Explicit enter starts immediately.
- Foot departure requires 50 seconds; motor departure requires 25 seconds, with
  at most 90 seconds between matching observations. Brief stops can rejoin a ride.
- Three-minute still grace, eight-minute evidence silence and twelve-hour session
  ceiling. Expiration, reboot, permission loss and opt-out retain only the
  confirmed portion, not elapsed time after the last evidence.
- Today's duration includes confirmed active time and completed sessions; midnight
  splits use actual local-day boundaries (including DST), capped per day, eight
  retained dates. Removed the old 30-second minimum ride length.
- Cycling headline follows metric-row typography and large-text layout with a
  chevron, cycling/stopped status and a 30-second expiry display refresh.
- Steps explicitly say "Steps today". Prior-day readings do not supply today's
  number, provenance, range text or goal progress; their detail/history remains.
- Remove action/care/visit preview from the overview. Care and Health Actions
  remain explicit menu destinations; no saved records are deleted.

## Core Motion adaptation

Android uses activity transitions plus 20-second Google activity sampling. iOS
uses a primary activity change listener and a separate manager requesting the
current native activity every 20 seconds while the app is active. Each request
stops after its first result; generation, authorization, owner and ledger epoch
guards reject callbacks after suspension, opt-out or an account change.

Core Motion reports the activity currently in effect when updates start, with
`startDate` identifying when that classification began. A received native current
snapshot therefore bounds a classified interval from that start to the request
time. Closed history intervals are bounded by the next native activity record.
Replay feeds ordered 20-second observations from these native intervals, skipping
already accepted timestamps; it does not extend an open history tail to the query
end. Unknown activity and timer ticks never provide positive cycling evidence.
Medium/high unambiguous Core Motion flags replace Google's numeric confidence
thresholds, which Core Motion does not expose.

iOS does not promise 20-second execution while suspended. Foreground reentry
recovers available Core Motion history (up to seven days; availability can lag),
then requests current activity. No location/route permission or new background
mode is introduced. Real-world sensor accuracy and background recovery still
require device validation; this is not Android foreground-service equivalence.
