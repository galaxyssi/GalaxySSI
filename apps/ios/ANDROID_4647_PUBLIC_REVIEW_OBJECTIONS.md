# Public Objections in Final Review (Android #4647)

Baseline: Android PR #4647, merge `05621e0c5333665f7c0cafa44e8ce027c9b55bc2`.
Only the iOS public-objection increment is included; later review/planner policy
changes remain separate PRs.

The final editor still receives full public reports only from its explicit
parents. Explicit dissent from other contributors is additionally supplied as
`additional_objections`, containing only host-assigned `id` and bounded `dissent`.
Their findings and assignments do not cross this boundary. Parents' reservations
are already in their reports and are not repeated as additional objections.
Independent workers continue to receive only direct-parent reports.

The audit instructions ask the editor to qualify, correct or withhold a draft
when a material reservation is overlooked. An objection is not proof, and it does
not override the deterministic table arithmetic. No additional model call,
invented role, vote or broader workspace authority is introduced.

Success, withheld drafts and disputed source tables preserve role-attributed
public reservations in original plan order. A narrow rejection receipt carries
only the validated review issue and explicit objections, never the rejected draft
or full reports. Localized headings distinguish model reservations from the
host-calculated table result. Existing 10-role/12-call/concurrency constraints,
cancellation and durable-publication guards remain in effect.

Four synthetic XCTest methods are authored for a controlled objection changing
an otherwise identical draft from acceptance to withholding, parent deduplication,
worker/non-parent isolation, disputed table separation and the 12-call boundary.
They have not been executed. Focused JS source contracts and iOS structure checks
are used; no native build, device run, model/scientific validation, full repository
check, CI monitoring or IPA generation is claimed.
