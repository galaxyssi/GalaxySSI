## Implemented

- Replace the actual URLSession public-search regex link extraction with an inert SwiftSoup DOM parser. Raw HTTP search stays separate from WebKit article rendering. Fixed dependency 2.6.0 uses Swift tools 5.0; exact upstream tag commit is pinned in Package.resolved and the app target links the product.
- Read result heading anchors/cards, exclude scripts/styles/navigation/headers/footers/advertisements, deduplicate fragment-normalized destination URLs, and return bounded result titles/excerpts. Small bare-anchor adapters remain supported.
- Read Baidu's direct `mu` destination only from its owning c-container heading, not unrelated metadata. Decode same-engine URL query redirects and Bing URL-safe base64 redirects; preserve unrelated external query URLs. Reject credentials, invalid base64, non-HTTP(S) schemes and oversized destinations. Existing actual-fetch public-host/HTTPS/redirect/body/time policies are unchanged.
- Recognize Baidu security verification title/captcha redirects as `source_verification_required`, not successful empty evidence. If other sources work, expose unavailable provider/error codes alongside successful results. Excerpts are returned as both excerpt and snippet for existing consumers. Explicit allowed-host filtering precedes final result truncation.
- Three native regression fixture sources cover cards/snippets, ad/navigation/script exclusion, duplicate fragments, redirects, scheme/credential rejection, direct Baidu card ownership and source verification. They are NOT executed.

## Sogou Image Search Follow-up

- The actual model image-search call previously forwarded image verticals into ordinary web endpoints and the intelligence layer discarded image fields. Image-only requests now use the Android reference's `pic.sogou.com/pics` public endpoint. Explicit unsupported image engines or mixed image/non-image selections fail clearly, without silently substituting generic web results. This implements Sogou only, not all Android image engines.
- Parse the exact inert initial-state script as JSON with SwiftSoup and JSONSerialization; do not execute publisher JavaScript or use WebKit. Examine at most 100 rows, validate absolute source/image URLs, require HTTPS media, reject localhost/.local names and credentialed URLs, deduplicate actual images and preserve original-versus-thumbnail fallback and bounded dimensions. Search results explicitly say their bytes have not been downloaded. Existing actual-fetch private-host/network restrictions still apply when content is opened.
- Return images, lead image, source page and excerpt through raw provider and intelligence evidence projection. Deduplicate images rather than source pages, retaining multiple images from one page. Plain-text document cache entries cannot satisfy image requests; image cache persistence is not implemented and those requests deliberately bypass the text cache rather than losing image identity.
- Carry unavailable-source diagnostics through the upper intelligence metadata, not just the raw provider. Added native parser and actual registry-to-evidence fixture sources, including two images from one page and unsupported-engine no-network checks. NOT executed. Existing Markdown image display is reused via model-selected image URLs; this does not claim real download, relevance, viewer/save, UI or device acceptance.

## Renderer Lifecycle Follow-up

- Shared monotonic 30-second health cooldown suppresses repeated WK startup after confirmed content-process termination or startup unavailability. Ordinary page/navigation/content errors, cancellation and normal timeout do not poison health. A rejected cooldown check does not extend the failure window; successful rendering clears it.
- The original request deadline now starts before DNS. A single-worker OperationQueue performs DNS preflight off the main thread; the caller checks cancellation/checkpoints/deadline while waiting. Queued preflight work is cancelled on exit and late results are closed out. A running OS getaddrinfo cannot be forcibly interrupted; its worker may remain occupied until the OS returns, so this is a bounded caller wait, not guaranteed hard interruption of DNS.
- Keep capacity wait, post-acquisition checks and WK rendering within that same deadline. Bound main-queue startup to at most five seconds, no automatic render replay. Existing per-request nonpersistent website storage/process pool, URL/public-address/same-origin, authentication, popup, media and dialog policies are unchanged.
- Unconditionally cancel/clean up the coordinator on every exit, including thrown checkpoints. Completion is single-shot and thread-safe; actual stopLoading/delegate removal/view release remains on the main queue. A cancelled queued start cannot later create a new WK view, and late extraction cannot replace a terminal outcome.
- Four native health/preflight fixture sources added, NOT executed. No actual WebKit termination/startup fault, main-thread congestion, cancellation race, DNS stall, process restart, UI or device recovery acceptance claimed. Android private-process directory/Binder APIs are not copied to iOS or claimed equivalent; WK lifecycle handling is the platform adaptation.

## Shared Research Budget Follow-up

- Actual native research uses one monotonic budget (explicit total timeout or 30 seconds by default), capped by the parent invocation. Every query and page fetch receives a remaining-time child with a hard deadline; progress-aware checkpoints cannot extend that child. Original invocation context, permissions and parent cancellation are retained.
- Validate all global and raw/decoded per-query engine IDs before any query/cache/network work. Native raw endpoints also reject unavailable engines and honor explicit supported engine IDs rather than adding unrelated default providers. This is the currently implemented iOS subset, not all Android engine adapters. The text cache lacks engine provenance, so explicit-engine requests bypass it instead of returning results from another engine.
- Apply existing Android fast/balanced/deep defaults (6/18/32 fanout, 6/15/35 second per-query caps), retaining explicit search timeout/fanout choices. These are caps/preferences, not claims that iOS implements that many independent adapters. Research children are also limited by remaining total budget.
- Queries with less than one second available remain unexecuted and receive skipped-budget receipts; execution counts reflect only started searches. Budget exhaustion does not start new page reads. Keep collected evidence and coverage, report unexecuted queries/partial status even if earlier documents were sufficient, and expose actual remaining/exhausted budget metadata.
- Four native fixture sources cover exhausted-budget partial evidence/no further queries/pages, validation of a later unavailable engine before an earlier search, default-versus-explicit limits and nonextendable progress-aware child deadlines. NOT executed. The helper is registered in the app target.
- The configured cloud round/tool follow-up below also clamps the existing outer model loop. Cancellation reaches existing cooperative checks and bounded request timeouts; immediate interruption of a transport already executing synchronously is not newly guaranteed. No live transport deadline/cancellation, fault, wall-clock-shift, UI or device acceptance is claimed.

## Configured Cloud Round And Tool Budget

- Reuse the current configurable CloudResearchRuntimeBudget, rather than restoring historical fixed 60/180-second defaults over later user settings. Compute overflow-safe monotonic remaining active time. Actual provider rounds, including compatibility requests, consume the smaller of their configured limit and remaining active time; recheck after audit/admission before starting transport.
- Queued parallel retrieval calls recheck remaining active time at task start. Exhausted calls return an explicit non-retryable stopped-tool result without invoking the executor. Other calls copy the original context and cap only retrieval timeout, preserving owner/turn/images/disclosure/read-only scope. A shared absolute deadline reaches the native registry; page-read follow-ups cannot obtain a fresh full tool allowance. Tools admitted by reserveTools are described as admitted, not falsely as executed.
- If a nonfinal provider round hits the shared deadline before answer text was emitted, request existing tools-disabled finalization with missing-evidence guidance. Its model time limit remains the user's configured value. Already-emitted answer text retains existing partial/error/evidence recovery behavior, not an unrelated appended replacement answer. No new collaboration admission/publication, tool visibility or effect permission is granted.
- Check parent task cancellation before queued tool execution and after the batch. Existing per-call durable observation callbacks, ordered output, evidence retention/validation, disclosure and scoped collaboration kernels remain. No immediate interruption of an already-running synchronous tool, process fault/restart or cancellation-race acceptance is claimed.
- Added two native fixture sources for remaining active/model/finalization limits and actual registry deadline/expired-provider suppression with original conversation/turn scope. NOT executed. These source checks do not prove the real multi-round or parallel workflow.

Keep at most four unique media candidates per source, bounded dimensions/title/alt, thumbnail/original references and source URL. Reject non-HTTP(S), credentialed and oversized media destinations without truncating them into another URL.

## Query-aware Search Completion

- Actual raw search now supplies parsed title, excerpt, source/provider and image URL to the early-completion policy, rather than counting all links as equivalent evidence. Explicit-source and deep searches do not end early. Prior disjoint-query diagnostics remain in force.
- Ordinary queries require at least 30 UTF-16 excerpt units and at least half the query tokens overlapping title/excerpt. Deduplicate canonical source URLs, require sufficient distinct domains, and require two engines for balanced completion. Fast and balanced result thresholds match the reference. Compatibility normalization, Latin model/version tokens, CJK bigrams and single-character CJK queries are supported; regexes are cached.
- Image-only completion counts distinct valid media URLs with valid source pages, not distinct page URLs, and does not invent additional engine/domain requirements. This is still discovered URL evidence, not downloaded bytes or visual/relevance proof. Legacy URL-only call defaults remain available, but the actual search path supplies typed evidence.
- Returning, timing out or ending early marks the request-local accumulator cancelled. Queued work and existing cooperative resource checks see that flag through scoped child invocations with hard request/global deadlines and original permissions/context. Already executing synchronous transport is not claimed to stop instantly, and abandoned providers are not proof of a network cancellation acknowledgement.
- Added four native fixture sources for substantial/related versus title-only excerpts, balanced source/engine deduplication, distinct images and explicit/deep behavior, and compatibility/CJK tokens. NOT executed. No live latency, source-count, semantic relevance or cancellation-race acceptance claimed.

## Encrypted Cache Persistence Follow-up

- Search result documents now commit as one bounded encrypted snapshot instead of rewriting the full file once per result. Document/watch/envelope v1 schemas and URL normalization remain unchanged.
- Distinguish an absent initial file from unreadable, corrupt or unsupported encrypted snapshots. Existing ciphertext is not overwritten after failed reads, and a missing or malformed key is not silently replaced. Serialize read-modify-write by standardized file path within this process and serialize key creation.
- Production writes use throwing atomic replacement and file protection until first user authentication. Cache clear and watch mutations report persistence failure instead of claiming success. Optional caching failure retains valid network evidence and exposes write_committed=false; it does not turn a successful fetch into a network error.
- Five additional native fixture sources cover corruption, missing keys, failed replacement, batch writes, multiple instances and actual tool failure feedback. NOT executed. Process-local serialization is not a cross-process/symlink-alias transaction; atomic replacement is not proof of fsync/power-loss recovery. Whole watch-check workflows across network calls are not CAS transactions.
- Full-snapshot reads/decryption remain synchronous. Deferred source learning, source-health indexing and workspace record/index atomicity are still incomplete; this cache increment is not equivalent to all Android maintenance changes.
