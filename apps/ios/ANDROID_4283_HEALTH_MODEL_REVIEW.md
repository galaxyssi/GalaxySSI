# Android #4283: structured automatic Health assessments

Source: https://github.com/galaxyssi/GalaxySSI/pull/4283

## Runtime mapping

- New automatic research jobs require a durable structured assessment. Missing
  optional markers keep existing jobs on their legacy completion path.
- The scoped cloud loop advertises the complete `galaxyssi.health.review.record`
  schema under provider-safe name `galaxyssi_health_review_record` for OpenAI,
  Anthropic and Gemini. It persists the assessment before acknowledging the tool.
- A proposed plan is an optional, unadopted draft. Its retained same-turn plan ID
  must precede a `PROPOSE_PLAN` assessment. Saving a draft alone no longer marks a
  new automatic review completed. A final prose response finishes the round.
- Paired Desktop returns a bounded assessment/optional-plan/answer envelope. The
  phone validates and retains it through the same scoped methods; Desktop has no
  new execution permission and requires no protocol or code changes.
- Exact current concern/record revisions, thread and turn, live authorization,
  local/online permissions, profile scope, provider configuration/credential digest,
  evidence receipts and plan receipts are checked. Identical in-turn retries reuse
  the first stored assessment; conflicting content, revoked or stale writes fail.
- iOS uses its existing profile-bound, AES-GCM encrypted and complete-protection
  Health archive. Assessments are keyed by turn and verified by write-readback.
  Optional Codable fields migrate existing data without a second Health database
  or copying Android's SQLite schema version into an unrelated iOS store.
- A missing assessment retains the final reply but marks the review failed and
  does not publish a successful research checkpoint. Stale input cannot complete a
  review. The scheduling ledger also rejects direct unverified completion.
- A prior assessment is shared only with matching permission/destination scope
  and the prior completed checkpoint. It is labeled a historical model opinion,
  never a verified clinical fact or an instruction.
- Existing research controls display summary, rationale, uncertainty, next step,
  decision and review conditions, with historical-data and non-diagnostic notices.
  Chinese text is confined to the Chinese localization resource. Sensitive display
  state is cleared on background/profile/protected-data changes.

## Boundaries

Recording does not confirm targets, alter medication, adopt steps, send attention
notifications, schedule reminders or close concerns. Conditions and attention
requests are recommendations for a later coordinator. This does not claim the
entire autonomous Health-management roadmap is complete.

## Verification

Focused XCTest source covers validation, encryption/reopen/readback, idempotency,
missing assessments, revoked/stale scope, same-turn plan ordering, paired Desktop,
the actual scoped cloud continuation, all three provider schemas, legacy decoding
and historical opinion sharing. Earlier automatic-research fixtures now record
an assessment before asserting completion.

Windows can run the iOS structure check, Swift grammar comparison and diff checks.
Swift type checking, XCTest execution and device behavior require Xcode/devices
and are not claimed from the Windows workstation. No IPA is generated by this PR.
