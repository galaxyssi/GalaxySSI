## Native Integration

- Replace the old long mixed list and per-Agent model menu with a compact current-conversation route summary, Automatic row, Desktop/cloud/on-device segmented sources, inline model rows, one expanded provider and a fixed footer outside the model ScrollView. Preserve real existing brand assets, adaptive colors, unavailable-selection warning, QR pairing, cloud setup and local model management. Model rows select directly without dismissing the page, including Automatic/local/cloud choices. Supported selected-Agent reasoning stays visible in the footer regardless of active source tab.
- Use actual ready local profiles, credential/availability-filtered cloud models and deliverable Agent targets from existing native registry APIs. Preserve separate Desktop computers; sort the selected Agent first, then Codex, with stable order otherwise. Copy the exact reference older-family ID sets; keep the selected older model visible, fold only other older models, show all when an older-only catalog would otherwise be empty, and accept future catalog IDs without a hardcoded new-model allowlist. Retired models remain excluded. Presentation labels never rewrite IDs or catalog entries.
- Reuse existing selection settings, remembered per-target model/effort and routing. Catalog/alias PR #4559 and future-chat defaults PR #4557 merged into main while this picker PR was being developed. Merge that main, rather than independently duplicating their changes. Preserve their canonical selection/default persistence; Desktop grouping uses the public normalizedModelId, and cloud selected-state uses CloudModelRequestRoutingPolicy.model so aliases and selected-default IDs resolve through the actual merged implementation. The future-chat remember hint appears ONLY if the actual default selection equals the current selection; otherwise show saved-for-current-conversation text. Do not restore obsolete menu rendering while resolving those merged changes.
- Existing routing/import/pairing notifications refresh the open picker. The routing-notification handler no longer sends another forced manifest request, preventing a manifest-response/request feedback loop. It bypasses prepared cache for new catalogs. Initial/manual refresh still requests the actual Desktop manifest through the existing coordinator; no MQTT/service changes. A reload icon is available even if the initial list is empty.
- Remove synchronous source construction from the uncached loading path. One structured async read builds content off-main; overlapping requests set a pending flag and trigger one trailing refresh after the current read returns. Keep current rendered content on same-conversation refresh. Cancelled/departed/old-conversation/old-profile reads do not publish. Already-started detached reads are not force-cancelled. Selection mutations require a visible, loaded snapshot belonging to the current conversation/profile; local readiness, current cloud credentials and current Agent/model/effort availability are rechecked before saving. This does not prove native scheduling, source I/O latency or backing-store profile isolation.
- Preserve existing Agent home header/layout, persistence schema, catalogs, pairing/service transport and dispatch policy. New UI/policy live in separate Swift files rather than growing the existing combined settings file. English fallbacks and Chinese resource keys cover new picker text; other languages retain the repository's existing fallback behavior, not a claim of complete translated-language parity.
