# Single-agent research calibration

The existing `galaxyssi.single-agent-calibration.v1` protocol remains unchanged:
one free-running dispatch, ordinary output, no research publication enrollment.
It measures execution and delivery, not persistent learning.

The explicit `galaxyssi.single-agent-research-calibration.v1` protocol gives the
same single member an ordinary production `EXECUTE` publication assignment.
The member receives the complete original objective, not a prescribed solving
sequence. It can use the existing group-scoped evidence, original archives and
versioned workflow candidates. The production worker owns enrollment, validation
and finalization; the test harness does not accept its own substitute schema.

This mode still has exactly one member and one phone dispatch. There is no goal
controller, recruitment or hidden team DAG. Provider-internal delegation must
be audited separately; a phone dispatch count is not a model request count.
Model and reasoning remain selected in the App. Saved candidates are unverified;
independent review and capability promotion rules are not bypassed.

Reports identify `execution_mode=single_agent_research`, preserve the original
milestone archive and retain `test_scope=execution_delivery_only`. Even a passing
delivery report cannot claim scientific correctness, capability gain or host goal
acceptance. An empty archive remains a valid null observation, not a method
formation success. The existing continuity protocol can preserve the same group
between separately registered tasks; new contexts must demonstrate actual reads
and relevant changes of action before claiming transfer.

Use this mode when comparing memory or method formation with a team. Giving only
the team persistent methods would confound collaboration with tool access. Keep
prior calibration results under their original protocols, rather than upgrading
their interpretation retroactively. Input quality, compute and provider costs
remain separate comparison requirements.

  verdicts, milestone archival and method experience.
- Debug application and instrumentation APKs assembled successfully.
- S20U (SM-G9880), Android app 1.4.150 (1235): five local device tests passed,
  covering the new one-member publication/next-task recall fixture, the existing
  single-agent contract, full coordinator context and workflow persistence.
- No real model, original research task, contact or device operation was invoked
  by these tests. The new fixture enrolls a synthetic assignment directly; real
  model enrollment through the production worker still needs separate acceptance.
- Runtime UI and Desktop source were not changed. This is experimental access
  parity, not evidence of autonomous method formation or transfer.
