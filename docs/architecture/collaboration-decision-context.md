# Decision context before publication format

An active research member needs the original objective, acceptance conditions,
current feedback and other members' evidence before it can decide what useful
work to do. A correct publication schema alone does not provide that context.

## Selection and presentation are separate

`CollaborationResearchPrompt` keeps the complete mandatory assignment, host
contract, authorization/evidence boundaries, response protocol and evolution
policy. It does not shorten validation requirements to fit more material.

Within the existing optional-context allowance, selection uses this order:

1. The full original goal and preserved acceptance criteria.
2. Current host feedback, peer messages, dependency evidence and assigned work.
3. Task-related capability references and observed problems.
4. Source mapping, inventories, directories and historical context.

This is a host-known operational priority, not a learned semantic relevance score
or a claim that every peer message is useful. Same-priority sections retain their
original order. A section that does not fit is omitted atomically, not clipped;
later smaller sections can still fit. Complete originals remain in the same
immutable goal-contract snapshot and available through scoped recall.

Presentation places the assignment, boundaries, actual resource observation, goal,
criteria, pinned contract and selected decision context before the full response
schema. Selection reserves all mandatory material and omission references first;
presentation cannot evict a contract or increase the existing character budget.

## No new authority or automatic uptake

Messages, dependencies, retrieved methods and tool feedback are evidence, not
instructions or permissions. Prioritizing them does not mark them read, accept a
claim, satisfy a criterion, install a skill or execute an action. The member still
chooses whether to test, challenge, reuse or reject a contribution.

Recovery preserves its existing snapshot binding. It does not refresh context
from newly arrived messages or silently replace the original goal. Omitted data
remains explicitly omitted, including dependencies marked as truncated by their
source. Another dispatch/checkpoint is required to receive newer context.

## Verification boundary

Regression tests exercise a context where optional bookkeeping would otherwise
displace a current peer contribution, compare presentation and allocation, and
preserve full required contracts, Unicode, omission references and recovery.
These are context-delivery properties, not evidence of better model reasoning.

Real-task evaluation must separately observe whether the member acts on a
counterexample, changes an executable candidate, corrects errors without new
regressions, and transfers a retained method to a fresh task. More inline evidence
or fewer recall calls do not by themselves demonstrate acquired capability.
